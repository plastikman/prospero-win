FONV, FO3, GTA IV, Oblivion, Bloodlines, and MDK. All six returned to the
launcher at the spinning-dots stage. Their PS5 app traces select each title's

### Package 1109 hardware launch: failure is earlier than the game

The descriptor-fix package was installed and launched. The first selected
profile was `oblivion-gog`, native CPU. It returned to the launcher before the
spinning dots. A subsequent launch selected `fallout-new-vegas`, also native,
and failed at the same point. These are not title-specific faults.

Both klog stacks are byte-for-byte the same wineserver startup path:
`fatal_error` -> `create_server_dir` -> `open_master_socket` ->
`start_inprocess_server`. Disassembling the exact package-matched
`wineserver.shared.elf` at the recorded return address (`create_server_dir +
0x316`, `0x8a8a6`) identifies the fatal branch as the source check
`if (home[0] != '/') fatal_error("your home directory %s is not an absolute
path")`. Therefore `create_server_dir()` did not see `WINEPREFIX` and fell
back to a relative `HOME`. The launcher klog does report setting `WINEPREFIX`
successfully before Wine starts, so the remaining question is why that value
is not visible to `getenv()` from the in-process wineserver module. Do not
attribute this to the games, Vulkan, or the descriptor queue, and do not ask
for another ordinary launch: the exact fatal branch is already established.
